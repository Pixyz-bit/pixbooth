# Pixbooth

Pixbooth is a browser photo and live-clip booth built with React. The canonical working project is `C:\Martin Archive\Programming\2026 Projects\PhotoPix`; the folder name is retained even though the public brand is Pixbooth. The supplied Pixbooth PNG logo is the identity asset. The authoritative site-wide visual guide is [docs/design/DESIGN-CONCEPT.md](docs/design/DESIGN-CONCEPT.md).

Start on the home page with its centered hero, supplied logo, subtle monochrome grid and illustrative photo-print composition. One Capture action enters `#/templates`, the first of three steps. There is no landing navbar. The locally generated grayscale sample artwork is labeled Illustrative sample captures; it is not a user's session or a testimonial. The home page has no interactive strip-design playground.

1. **Choose template — `#/templates`.** Browse the 21-layout grid, initially selecting the four-photo Classic strip. A separate selected-layout diagram and capture count accompany Continue to capture. Continue enables the capture step.
2. **Capture photos — `#/booth`.** Choose Photo or Live mode, explicitly enable the camera, and capture one item per click with a 0/3/5-second countdown. The sidebar contains only face stickers; the full camera and two-column captured-media gallery lead, with collapsible photo settings below the gallery. The logo is in the shared workflow navigation, without a duplicate inside the camera panel. The camera contains the full source frame; gallery cards use centered crops following the selected template's frame proportions. Capture mode and the initial template lock after the first item.
3. **Edit & download — `#/edit`.** After all required items are captured, Submit opens the final editor. Compatible same-count layouts and finishing choices belong here.

Non-home pages share semantic step breadcrumbs. The current link uses `aria-current="step"`; capture is unavailable until Continue, and editing is unavailable until capture is complete. Available previous steps remain clickable. Captures and editor choices survive backtracking and browser history in memory. Returning to the template step after a capture shows the locked layout; Start over is required to choose another capture layout.

Choose None or one of 36 face-tracked effects from Animals (8), Eyewear (7), Headwear (10), and Fun (11). Search by name or category. Thumbnail, live overlay, and captured media use the same canvas artwork renderer. Effects are baked into each capture; switching between active effects retains the face-tracking worker.

In the final editor, choose a compatible layout with the same number of captures, eight original decorative frames plus No frame, 20 backgrounds, 20 photo filters, 11 surrounding border stickers plus None, and a caption of up to 32 characters. Photo mode downloads a JPG. Live mode records silent five-second H.264 MP4 clips, provides individual clip downloads and an animated editor preview, and creates a five-second composed MP4 with a JPG cover-photo download. MP4 availability depends on the browser's encoding and decoding capabilities; Photo remains available when Live is unsupported. Recording and export support cancellation.

Output geometry is fixed per template and independent of webcam resolution. The base is 900 × 675px photo cells, 36px padding, 23px gaps, and a 126px caption footer. Square, Portrait, Polaroid, Film frames, and mixed-size layouts define their own frame geometry. Source media is center-cropped to fill each output frame. JPGs use the full template dimensions; composed MP4s preserve the template proportions, scale their longest side to at most 1920px, and use even pixel dimensions. Editor choices are applied through the shared strip renderer. Decorative frames inset photo openings while retaining the same fixed output dimensions. Finished editor strips display immediately without a printing animation. The template catalog also supports name search, photo-count filters, clearable empty results, and Pick for me.

Photos, clips, and editor choices stay in browser memory and disappear on reload. Fresh or reloaded `#/booth` and `#/edit` URLs without session state return to `#/templates`. An in-session edit URL before capture completion returns to capture if Continue has already been used. Start over clears captures and editor choices, returns to step one, and leaves the camera off. Navigation away from capture cancels countdown/recording and stops camera tracks. Tracks also stop on completion, explicit cancellation, and unmount. No uploads, accounts, backend, or persistence are required. Face detection runs on the CPU in a browser worker with locally served MediaPipe 0.10.32 assets. Photo pixels, clips, and landmarks are never uploaded. Real-camera and mobile-device compatibility require device testing.
